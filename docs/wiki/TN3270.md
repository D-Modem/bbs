IBM 3270 terminals and their emulators get full 3270 screens, with PF
keys. If the terminal has graphics, they also get graphics. This page
tells how the BBS recognises a 3270, the keys, and how the BBS draws
pictures.

A 3270 client connects to the telnet listener in the same way as all
other clients. The BBS asks each client for its terminal type. If a
client says `IBM-3278-*`, `IBM-3279-*`, `IBM-3277-*` or `IBM-DYNAMIC`,
the BBS gives it to [go3270](https://github.com/D-Modem/go3270). go3270
negotiates binary and end-of-record mode. It finds the screen size (from
24x80 up to the 27x132 of the model 5, or the size that IBM-DYNAMIC
gives) and the code page. Then the caller gets the 3270 screens:

| Key | What it does |
|---|---|
| Enter | log on, select an option of a menu (by its letter), select (type `S` adjacent to a line), save |
| PF3 | back, log off |
| PF5 | new user (at the logon). New scan (the areas). Read new (in an area). Send (in the editor). Reply by mail (in a message). Change your location (the profile) |
| PF6 | post (in an area), new mail (in the mail), add an area (the sysop), your password (the profile) |
| PF7 / PF8 | up / down a page, or the text of the message |
| PF4 | reply. Messages to you (the areas) |
| PF9 | delete, remove |
| PF10 / PF11 | previous / next message. Find messages / scan setup (the areas) |

The key line at the bottom of each screen shows which of these keys the
screen accepts. The screens are the same as the screens of the text BBS
(refer to [Development](Development#screens)). The selections are the
same, but you make them with PF keys, not with letters.

```
c3270 localhost:2300
x3270 -model 3279-4 localhost:2300
```

With `tn3270 = no` on a listener, the BBS sends the text BBS to 3270s.
They cannot show it.

## 3270 graphics

When a terminal connects, the BBS reads all the data that the terminal
reports about itself (its query replies). It uses all the graphics that
the terminal has:

| Feature | Terminals | Used for |
|---|---|---|
| graphic escape (code page 310) | almost all: x3270, c3270, wc3270, PCOMM, Vista | the box around the main menu, rules, bar charts in System info. ASCII if not. Pictures in blocks where there are no vector graphics |
| programmed symbols | IBM PCOMM, HostExplorer, Quick3270 | the logo on the logon screen: the name of the system in a pixel font, or `tn3270_logo` (a PNG), cut into character cells and loaded as a symbol set. Pictures where there are no vector graphics |
| vector graphics | PCOMM (host graphics, native protocol), HostExplorer | pictures, in the colours of the terminal, and the logo as a bitmap image in place of symbols (`tn3270_vector`, enabled by default) |

### Pictures

The BBS draws pictures from the image boards (the thumbnail of a post,
and the full image) with the best method that the terminal supports. It
uses this sequence:

- **Vector graphics** (PCOMM): the picture as bitmaps, one pel for each
  pixel. Error diffusion changes the picture to the palette of the
  terminal: the 16 colours of PCOMM (its Graphic Color reply), which
  include orange, purple, the dark shades and grey. The BBS paints each
  colour over the other colours, because the exclusive or of PCOMM does
  not combine blue with the other colours. The BBS keeps the cells below
  a picture empty, and puts the cursor in a different location. On
  PCOMM, a character over a picture clears the picture in its cell.
- **Programmed symbols** (HostExplorer, Quick3270, PCOMM with vector
  graphics disabled): the BBS cuts the picture into character cells. Each
  cell is a symbol. The BBS loads the symbols into the symbol sets of
  the terminal before the screen. A set holds 190 symbols. Thus, the
  size of the picture is the number of cells that fit in the available
  sets. A blank cell does not need a symbol, and identical cells share
  one symbol.
  - With **triple-plane (colour) sets**, and the extended Load PS that
    loads one plane at a time (PCOMM with only programmed symbols has 3
    such sets and 3 single-plane sets): each pel can be one of 8
    colours, from the sum of its blue, red and green planes. Error
    diffusion changes the picture to these colours. A cell of more than
    one colour goes in a triple-plane set. The BBS loads its planes one
    at a time and shows them neutral (X'F7', which shows the planes of a
    cell). While there is space, a cell of one colour and black goes in
    a single-plane set in that colour. This keeps the colour sets for
    the other cells.
  - With only single-plane sets (PCOMM with vector graphics also enabled
    has 2: 380 cells): each cell has one of the 7 colours of the 3270,
    the colour nearest to its pels. Its symbol has its pels on or off,
    with error diffusion.

  `tn3270_symbols = no` disables them, for pictures and the logo.
- **Blocks** (x3270, and all colour 3270s with graphic escape): ▀ ▄ ▌ ▐
  █ in the 7 colours of the 3270. A cell is two pixels by two. Each cell
  has the colour and block nearest to its four pixels.
- **Words** on all other terminals: `[cat.png, 640x480, 52 KB]`. All
  terminals also show this text below the picture.

A caller can disable and enable pictures in the profile (M, or PF11).
The terminal line of the profile shows the method that the BBS uses.

PCOMM sends its graphics query replies (the Segment reply that says that
it has vector graphics, and its colours) only when the host asks for
them by name. Thus, the BBS sends a Query List for each item in the
Summary reply of PCOMM that did not come with the first Query.
`cmd/gfxtest` in [go3270](https://github.com/D-Modem/go3270) is a 3270
server to try vector graphics on an emulator. It logs each record in the
two directions.

Option T of the 3270 main menu, *Your terminal*, shows the data that the
terminal reported: its code page, cell size, graphic escape, symbol sets
and Load PS formats, vector graphics, and all query replies in hex. The
log has a line with this data for each 3270 that connects. If an
emulator does not show the logo, start your checks here.

In PCOMM, programmed symbols and vector graphics must have host graphics
enabled in the configuration of the session. Vector graphics must also
have the native protocol (refer to the *3270 Emulator User's Reference*
of PCOMM, "Host Graphics").
The formats come from the
[3270 Data Stream Programmer's Reference, GA23-0059-07](https://bitsavers.org/pdf/ibm/3174/GA23-0059-07_3270_Data_Stream_Programmers_Reference_199206.pdf)
of IBM and the [3270 Graphics](https://www.prycroft6.com.au/misc/3270grfx.html)
of Greg Price.
